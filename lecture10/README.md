# Лекция 10 — Егоров Дмитрий

1. Создайте отдельную пустую учебную базу PostgreSQL 16. Выполните `lecture_10_seed.sql`, затем `setup_l10_tasks.sql`.
2. Откройте три независимых подключения к этой базе и схеме public: A, B и M. Проверяйте разные PID. В испытании использовалась база `new10_egorov_20261103_v2`.
3. Откройте `lecture10_Egorov.sql`. Выполняйте только очередной пронумерованный шаг в указанном подключении; файл целиком не запускать. Подключения A/B/M и порядок переключения обязательны. Во время ожидания блокировки завершайте переключения за две минуты; затем сработает lock_timeout.
4. Для ожидающего UPDATE оставьте окно работающим и переходите к следующему шагу в другом подключении. В deadlock оба окна могут ждать; сразу выполните диагностику в M. Автоматическое обнаружение обычно происходит примерно через секунду, поэтому цикл вручную можно не успеть снять; он сохранён в фактическом журнале M. Жертва deadlock при повторе может быть другой.
5. Ошибки P0001 (нет получателя), 55P03 (NOWAIT) и 40P01 (deadlock) намеренные. После них выполните указанные ROLLBACK; проверьте SUM и отсутствие открытых транзакций. При неожиданной ошибке откатите A и B и прекратите опыт.

`report.md` и `results/results.csv` содержат факты прогона, `results/session_*.log` — SQL и ответы сервера с UTC-временем. Запуск выполнен драйвером psycopg. Для повторения нужна новая база: seed идемпотентно добавляет отсутствующие строки, но не сбрасывает уже изменённые балансы. Таблица l10_tasks отсутствовала в оригинальном seed; отдельное минимальное дополнение создаёт её пустой исключительно для требуемого COUNT(*).
