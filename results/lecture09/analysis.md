# Работа 9: представления

Исходные данные — `lecture08`: 1 000 клиентов, 2 000 товаров, 120 000 заказов и 480 000 позиций. Файл `lecture_09_seed.sql` не был предоставлен; набор из слайда 22 не воспроизводился.

Обычные VIEW оставлены для сумм заказов и показателей клиентов: они отражают текущее состояние источника. Две MV сохраняют дневные агрегаты для повторных отчётов. Их можно читать быстро, но актуальность зависит от последнего REFRESH.

| Запрос | Строки результата | Buffers hit / read | Temp read / written | Execution, ms |
|---|---:|---:|---:|---:|
| Расчёт через VIEW | 68 | 5362 / 0 | 2711 / 2720 | 1024.788 |
| Чтение MV | 68 | 1 / 0 | 0 / 0 | 0.065 |

В плане VIEW выполняются соединение и агрегирование исходных заказов и позиций; план MV читает сохранённые дни. Полные планы рядом в `15_plan` и `16_plan`. Времена — один запуск на PostgreSQL 16.10, а не гарантированная скорость.

Контрольная выручка: **63181080000.0**. Источник, заказы, клиенты, дни, категории и месяцы дали одинаковую сумму. По каждому дню различий нет; все 1 000 клиентов сохранены, у 150 нет состоявшихся продаж.

В проверке свежести цена одной позиции временно увеличена на 1. VIEW сразу изменился, MV сохранили прежние суммы. После REFRESH суммы совпали. ROLLBACK отменил тестовую правку и обновление MV; исходные данные сохранены (файл `19.csv`).

Среднее за семь календарных дней рассчитано после добавления отсутствующих дат с нулевой выручкой. Окно по семи строкам исходной MV означало бы семь дней с продажами, между которыми могут быть пропуски.
